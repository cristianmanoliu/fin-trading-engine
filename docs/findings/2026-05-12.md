### D3 — PARTIAL canon to terminals-only (commit `c931842`)

Two tools disagreed on whether PARTIAL close events count toward the
150-trades + WR gates:
- `stage_promotion_check.py::load_journal` (formal gate): TERMINALS
  ONLY (skips PARTIAL)
- `forward_paper_status.sh` awk: every close counted + PARTIAL
  contributed to wins

Today the divergence is invisible (live config = single 6:1 RR, no
B2/multi-TP, zero PARTIAL emission). With B2 re-enabled the dashboard
would inflate trade count + WR above the formal gate, fracturing the
operator's mental model at promotion time.

Resolution: terminals canonical. Reasoning anchored on CI math:
multiple PARTIAL exits from one entry share the same alpha source →
not independent → multi-counting inflates trade-count CI without
bounding it. PARTIALs realize real dollars (so PnL/fee/slip accrual
is preserved) but they share the parent entry's alpha — at the
decision level they're one trade.

Dashboard changes:
- awk block: `total` + `wins` only count non-PARTIAL closes; new
  `partials` counter tracks PARTIAL events separately. PnL / fee /
  slip / notional still accumulate from ALL closes.
- `STRATEGY|...` line gains trailing `partials` field. Internal-only
  format; only `forward_paper_status.sh` itself consumes it
  (`paper_live_compare.sh` has its own independent format).
- `NODATA` emit condition relaxes: only when both `total==0` AND
  `partials==0`. A partial-only mid-flight cohort (B2 enabled, one
  PARTIAL realized, no terminal yet) now surfaces a STRATEGY line.
- "Trades closed: N / 150" shows terminal count. When `partials > 0`,
  extra line surfaces: "(+ K partial closes; not counted in
  trades/wins per D3 canon)".
- `stage_promotion_check.py::load_journal` docstring rewritten —
  removes the "drift with the dashboard" framing (sites now agree).

New tests (`PartialCanonD3Test`, 3 cases): fixture-driven assertions

### D4 — KILL-vs-DEPLOY-FAIL taxonomy (commit `223d865`)

Dashboard previously routed several deploy-criterion FAIL states to
verdict lines prefixed `KILL —` despite CLAUDE.md having no
corresponding kill criteria:
- `s_fee == FAIL` (fee > 12bp) → "KILL — realized cost exceeds kill threshold"
- generic disjunction → "KILL — at least one criterion failed"

Real risk path: at Layer 2 testnet activation when real Binance fees
replace the modeled flat-rate 10bp Stub costs, a thin-liquidity
symbol's fee could legitimately land at 13-15bp and trigger the
"KILL —" message. Operator following the dashboard literally would
have invoked the auto_kill_execution flow inappropriately.

Resolution: five-class verdict taxonomy:

| Verdict | When | Operator action |
|---|---|---|
| `KILL — advisory` | s_slip_kill==FAIL (slip > 25bp) OR s_hodl_window==FAIL | Confirm via drift detector; this IS a CLAUDE.md kill criterion |
| `DEPLOY-FAIL` | Any deploy criterion FAIL with NO kill criterion firing | Investigate; do NOT auto-kill; promotion blocked |
| `WAITING (insufficient data)` | < 60d OR < 150 trades | Continue accumulation |
| `DEPLOY-READY` | All locked deploy criteria PASS | Reach for the STAGE_1 checklist |
| `WAITING` | Catch-all intermediate state | No action |

Specific messages reference the threshold + the criterion class
explicitly, e.g. "DEPLOY-FAIL — realized fee exceeds 12bp deploy
threshold (investigate; no fee kill criterion)".

T13c/T13d existing tests renamed + assertion strings updated to the
new taxonomy. NEW test `test_fee_fail_routes_to_deploy_fail_not_kill`
exercises the formerly-mis-labeled path: 160 closes × 15bp fee × 5bp
slip asserts the verdict is DEPLOY-FAIL on fee, NOT KILL.

NOT changed: all `s_*` per-criterion statuses, all threshold values,
`forward_paper_resolution.py` (consumes structured numerics, not
verdict string), `auto_kill_execution_decision_rule_2026-05-08.md`
flow logic.

## Surprising findings

### D1 was a label-only drift, not a semantic conflict

The most useful single observation today. The T12 finding doc framed
TIME-ANCHOR as a 3-way ambiguity needing operator resolution. On
careful re-reading: the implementation was always correct (first-close
via `event == "close"` filter); the labels added 2026-05-11 PM were the
actual drift. The line 134 "forward-paper start" reference is calendar
projection prose, not a gate definition.

Generalizable: when a finding doc summarizes an "ambiguity between N
positions," re-read the source docs in CONTEXT before accepting the
ambiguity framing. Prose-projection vs gate-definition is a real
distinction that finding-doc summarization sometimes loses.

### Spec-impl-drift comes in four flavors

Of the 5 spec-impl drift instances surfaced 2026-05-11 PM:
- **T13c** (slip threshold) — real value drift. HIGH severity.
- **T14** (entry.go fallback) — real value drift. HIGH severity.
- **T12** (D1, time anchor) — label-only drift. Impl was correct.
- **T13a** (D2, BTC-HODL notional) — stale-text drift. Spec text
  written one day after fleet shrank; never updated.
- **T13b** (D3, PARTIAL) — latent divergence. Two tools disagreed but
  zero PARTIAL emission today made it invisible until B2 re-enabled.

Three of five were NOT live numeric bugs. The
spec-implementation-drift-on-ambiguous-locked-rule lens is firmly
predictive of all four classes — but predictiveness doesn't equal
severity. Future audit sessions should expect a mix; the mechanical
enforcement (`test_criterion_coverage.py` + `safe-push.sh`) catches
all four classes uniformly by pinning value-against-impl-sites.

### Pre-registration-amendment-on-stale-spec is legitimate

D2 set a precedent. Pre-registration discipline says locked rules
don't change mid-cohort to make the gate easier. The $32k → $16k
amendment is NOT that — it's correcting the description of what we're
testing, not relaxing the test itself:
- Comparison itself stays intact (cumulative PnL must beat HODL at
  equal notional).
- Fleet downsizing happened pre-pre-reg-lock (2026-05-07 vs 2026-05-08),
  not mid-cohort.
- Stale drafting carryover ≠ substantive criterion choice.

The 4 `results/*_2026-05-12.md` amendment docs establish a template
for future amendments: dated, scope-explicit, rationale-explicit,
forward-paper-continuity-explicit, lineage-explicit.
