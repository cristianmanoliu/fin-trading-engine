## BUG 1 — Gate A blocked the first-ever Layer 3 parity event (units bug in locked spec)

The first live signal to reach the Layer 3 testnet shadow since enablement —
KAVAUSDT SHORT, 2026-06-10 04:00 UTC (entry 0.0416, stop 0.0435435, 4.67%
stop distance) — was rejected:

```
Gate A failed: max-position cap $1000.00 exceeded (current_open=$0.00 + intent=$21404.68 = $21404.68)
```

Root cause: the locked pre-reg spec'd Gate A as "total $-notional per symbol
≤ N × stake" with the parenthetical intent "one position max per symbol;
matches paper-trading". Intent was a CONCURRENCY cap; the formula is a SIZE
cap in the wrong units. The strategy risk-sizes entries (qty = stake /
stop-distance), so notional runs 20–50× stake by construction. At N=1 the
gate rejects 100% of realistic orders, at every stage — STAGE_1 real money
included. The parity event is unrecoverable (cannot retroactively place the
testnet order); the parity clock restarts at the next KAVA/ENS signal.

Aggravator: the Layer 2 integration test helper had worked AROUND the broken
gate (`bl.SafetyGates.MaxPositionMultiple = 1e9` with a comment acknowledging
the block) instead of flagging it — writer-equals-fixture pattern, now the
4th instance.

Fix (`pkg/execution/binance_live.go`): Gate A basis notional → per-trade risk
(`qty × |entry − stop| ≤ N × stake`, N unchanged). Missing/zero stop fails
closed. Concurrency stays enforced by the upstream position-already-open
guard. `GateContext.OpenPositionNotionalUSD` (always 0 by construction)
removed; `SignalStopPrice` added. Regression test pins the exact KAVAUSDT
geometry: `TestSafetyGates_GateA_RealisticNotionalPasses`. The `1e9` test
workaround is deleted — integration tests now run the production gate.

## BUG 2 — Gate B would censor 24h of parity per stop loss

`DailyLossUSDCap: 1000` was hardcoded ("sized for STAGE_1", i.e. the $100
stake → 10×). Layer 3 shadows run the $1,000 paper stake, where one typical
stop loss is $1,061–$1,247 (incl. fees/slip) — a single loser would trip the
24h circuit breaker and silently censor the parity window after every loss.
Fix: constructor default is `10 × stake`; stage activation still overrides
explicitly per the protocol table.

## BUG 3 — the gate-block alert never reached the operator (Telegram 400)

The Gate A block fired a SeverityWarn alert; it died with `telegram API 400`.
Cause: `parse_mode: "Markdown"` + `current_open` in the message — a lone
underscore is an unterminated italic entity and Telegram rejects the whole
message. Audit of all senders found NO intentional Markdown but pervasive
underscore content (`ws_url`, `lag_p50_ms`, `BINANCE_API_KEY`, `--executor=
binance_live_testnet`) — an entire class of alerts (startup failures, Layer 3
mode banner, heartbeat bodies) was silently at risk. Fix: parse_mode removed,
plain text; contract locked by `TestSendBody_NoParseMode` (fixture is the
exact lost KAVAUSDT message shape).
