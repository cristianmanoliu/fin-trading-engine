## F1-F6: Script-layer audit pass (3 commits, 70 test assertions)

### F1 — run_drift_check.sh corrupt-history (commit `3b664f1`)

The wrapper read `drift_check_history.jsonl` through `jq` inside a
`set -euo pipefail` while-loop. A single malformed line (kill -9 mid-write,
disk-full, manual edit) aborted the wrapper with jq's parse exit code (~5),
bypassing the case→Telegram dispatch that only handles 0-4. weekly_audit
propagated the unmapped exit to launchd. **Decision-grade kill mechanism
silently dies on the only failure mode that matters.**

Fix:
- Per-line lenient parse with explicit MALFORMED counter
- New exit code 5 = HISTORY_CORRUPT routed to Telegram WARN with sample
  malformed entries embedded in the alert
- When MALFORMED > 0, suppress AUTO-KILL even if the rule would trip —
  cannot trust the rule against partial data
- Lenient pattern also applied to the bottom `tail -5 | jq` display path
- Env-overridable paths (DRIFT_CHECK_DETECTOR/HISTORY/RUNS_DIR) for testability

23 regression assertions in `scripts/test_run_drift_check.sh`. Bash test
infra wired into CI as a new `test_*.sh` loop step in the python-tests job
(auto-discovers future bash tests).

### F2-F5 — weekly_audit.sh tier classifiers + UNEXPECTED branches (commit `92b5772`)

Bundle of four fixes sharing a common testable-classifier infrastructure
extracted under a `BASH_SOURCE != $0` source guard.

**F2 — ssh-vs-validate misclassification.** ssh exit 255 (connection refused
/ auth / signal) hit the `≥ 2` test and routed to CRITICAL "journal_validate
found errors in live journals." Wrong tier (transient network ≠ corruption)
AND wrong text — the operator wakes up at 3am investigating non-existent
journal corruption. `_classify_validate_exit` separates ssh-level exit codes
(126/127/130/137/255) from journal_validate's documented contract (0/1=OK,
2/3=CORRUPTION). Distinct WARN tier + explicit "ssh issue" text. Also added
`BatchMode=yes ConnectTimeout=10` to fail fast on dead sessions.

**F3-F5 — silent fall-through on unexpected python exits.** All three case
statements (`kill_protocol_check`, `stage_promotion_check`,
`forward_paper_resolution`) had `*) :` swallowing exits outside the
documented contracts. A python crash (SIGKILL → 137, OOM → 137, uncaught
exception → arbitrary) silently routed to "no alert."
`_classify_python_exit` returns a semantic tier per helper's contract;
UNEXPECTED catches everything else. Each case now has an explicit
UNEXPECTED branch firing WARN.

31 regression assertions in `scripts/test_weekly_audit.sh` covering all
four classifier contracts including ssh-255 and python-137 SIGKILL.

## F7 — SSH-flag sibling propagation (commit `f0cbbbe`)

The F2 fix added `-o BatchMode=yes -o ConnectTimeout=10` to the
weekly_audit ssh call. AUDIT_LENS principle "always check the sibling" —
same shape exists in every other operational ssh caller.

**Highest-stakes sibling**: `forward_paper_status.sh:60` (`--live-source
vps` mode) is invoked by weekly_audit step 2. Same cron context as F2;
without timeout flags, a dead Hetzner connection would hang weekly_audit
for the full TCP retransmit timeout (~75s+) blocking the snapshot stage.

Hardened sites (22 total):
- `forward_paper_status.sh`: 1
- `paper_live_trades.sh`: 1
- `post_deploy_check.sh`: 16 (operator-invoked but STRICT mode could
  plausibly become cron-promoted — defense-in-depth)
- `stage_promotion.sh`: 5 (line 433 already had ConnectTimeout=5; added
  BatchMode for consistency, not a new fix)

Convention pinned by `scripts/test_ssh_flags.sh` — static lint that walks
each operational script, identifies real ssh invocations (filtering
string-literal shapes — "Run: ssh ..." in alert text, echo'd help text,
assignment-into-message literals), asserts each carries both flags. 24
compliant invocations, 0 violations. New ssh callers added without flags
fail CI.

The lint refinement itself was a Mode-3 instance: first cut had 5 false
positives. Iterated through 5 explicit string-literal shape filters until
all 4 false-positives were correctly skipped without dropping the 1 real
finding (stage_promotion:433 missing BatchMode).
