### Track 2: Python-side audit (commit `c1775a2`)

`realized_cost_trajectory.fetch_remote` was hardened against
shell-injection-via-f-string in an earlier session. The lens-pattern-
lock memo said to sweep siblings. Three decision-grade tools shipped
the same unsafe shape:

```python
cmd = f'ssh {vps} "tar -cf - -C {remote_dir} . 2>/dev/null"'
subprocess.run(cmd, shell=True, ...)
```

`vps` and `remote_dir` are operator-controlled (--vps, --live-dir).
With shell=True, metacharacters propagate to the local shell.

Applied realized_cost_trajectory's fix to:
- `live_vs_backtest_drift.load_remote_trades`
- `kill_protocol_check.fetch_remote`
- `stage_promotion_check.fetch_remote`

`scripts/test_remote_fetch_no_shell_injection.py` pins the fix two ways:
1. **AST scan** — no `subprocess.run(..., shell=True)` anywhere in the
   four target scripts. AST-based because substring search yielded
   false positives on legitimate comments (realized_cost_trajectory's
   inline "Avoid shell=True with f-string" lens-documentation comment)
   and error f-strings (`f"ssh fetch failed: {e}"`).
2. **Behavioural** — monkey-patch `subprocess.run`, drive each
   fetch_remote with an evil remote_dir containing `;` `$()` `"`,
   assert first call is list-form starting with "ssh" and the
   metacharacters aren't present unquoted in the remote command.

Bonus cleanup: dropped `["python3", str(path), "--quiet"] if False else ["python3", str(path)]`
dead conditional in `forward_paper_resolution.invoke_sibling`.

**Pattern locks**: silent-on-corrupt-input now 5-of-5 (no new sites
discovered today AM survived); shell-injection-via-f-string locked at
4-of-4 (realized_cost_trajectory + 3 siblings + pattern-pin test). Both
firmly predictive.

### Track 3: daily_status one-shot (commit `662fbd6`)

the --local + positional VPS conflict guard.

Designed for both interactive (`./scripts/daily_status.sh`) and cron
(`./scripts/daily_status.sh --quiet`) use. Exit codes map cleanly
onto Telegram tiers: 0 silent / 1 WARN / 2 CRITICAL / 3 CRITICAL.
