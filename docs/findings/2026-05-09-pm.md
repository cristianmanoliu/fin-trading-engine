`real_money_protocol_decision_rule_2026-05-08.md` defines four stage
transitions (paper → $100 → $300 → $500 → $1000); without mechanizing

After shipping the multi-stage extension I applied yesterday's audit
lens to it. Three real fail-opens surfaced:

1. **`check_recent_window_stability` no-losers → PASS**: gate is "fee/slip
   stable" but slip is unmeasurable when no losers exist in the window.
   30-trade winning streak would have green-lit a moderate-stake
   promotion without slip evidence. Now PENDING.

   "0 firings = clean" semantics treated empty file as success.
   Operator would see CONTINUE while reality was "no monitoring."
   Now PENDING with explicit "no parseable runs" message.

### Path 1+5 (3): CI lint + lessons memory

Multiplicative payoff: every future PR gets shellcheck + ruff. The
specific patterns that catch about half of the 13 fail-opens to date:
SC2086 (unquoted vars), SC2155 (declare-and-assign masking returns),
SC2087 (unquoted heredoc EOF), SC2164 (cd without exit guard), F841

Two-tier shellcheck:

- **Operational scripts** (forward_paper_status, post_deploy_check,
  weekly_audit, run_drift_check, paper_live_*, lib/, deploy/) lint at
  warning severity. Safety-critical; warnings stay closed.
- **Whole repo** lints at error severity only — catches real bugs in
  historical sweep/analysis scripts without forcing a refactor of
  locked research artifacts.

Ruff `--select F` (pyflakes) repo-wide. Style rules (E/W) NOT enforced
— project hasn't standardized.

Auto-fix sweep cleaned 119 cosmetic findings (96 F541 + 18 F401 + 8
F841 with `--unsafe-fixes`) plus 4 manual fixes (SC2034/SC2087/SC2164/SC2296)
in safety-critical scripts. 35 files touched, 120 tests pass.

slog.Warn (paper trading; missed writes are an analytical
